### Left for the owner
- Cancelling or changing a card is not self-service. "Manage or cancel" opens a note asking the customer to email via the Help page, and you then cancel by hand in the Stripe dashboard. That is honest (nothing on our side pretends to cancel while Stripe keeps charging), but it is friction at the exact moment people decide whether to stay, and a customer whose card bounced has no "update card" button even though the payment-failed email sends them to the Plans page with a button labelled "Update payment details". Recommendation: switch on Stripe's hosted Customer Portal (a few minutes in the Stripe dashboard) and add a small Edge Function create-portal-session that the Manage button opens. It handles cancel, resume, card updates and invoices, and the existing webhook already records the results. Until then, consider relabelling that email button "Contact us" so it does not promise a form that is not there.
- A customer whose renewal failed (Stripe calls it past_due) is shown "You're on Free" with an "Upgrade now" button. Clicking it creates a second subscription on the same Stripe customer while Stripe is still retrying the first, so they could end up paying twice. Nobody is in that state today (0 past_due rows), but the path is live. The portal above fixes it properly; the cheap guard belongs in create-checkout (listed under shared-file changes). Your call whether the page should also say "your last payment did not go through" in that state; I left the copy alone.
- Abandoned checkouts appear on the Orders page as "Awaiting Payment" with a Delete button that cannot work: 26 book orders and 1 canvas order sit in that state right now across all users, and the order tables give users no delete permission, so every attempt ends in "This order couldn't be removed." Options: (a) let people delete their own unpaid orders (one policy per table, written out under shared-file changes), or (b) do not list unpaid orders at all, since there is no "pay now" button to finish them. I recommend both: hide them, and allow the delete so support can tell someone to tidy up if ever needed. Tell me which and I will make the page change.
- 179 of the 182 subscription rows are placeholder Free rows (ids like "free_...") and one Premium row is a manual "admin_" grant until 21 Nov 2026. The page handles them correctly (Free shows Free; the admin row shows "Renews on 21/11/2026", which for a manual grant really means "ends on"). Only worth a change if you grant Premium by hand more often: then "Renews on" should read "Until" for rows without a real Stripe id.
- The Plans page quotes £3.99, $5.99 and €4.99 a month, the same as the pricing page. The real amounts live in Stripe price IDs in the Edge Function's environment, which the code cannot read. Please glance at those three Stripe prices once to confirm they still say 3.99, 5.99 and 4.99, because the page cannot follow them if they change.
- Orders show the destination as "London, GB" (the country code Stripe stores). If you would like the country spelt out, that is a small change I can make.
- The six paid orders on file predate the amount_charged column, so their cards show the product price (for example £44.99) rather than the total including delivery. New orders record the real total. Nothing to do unless you want a "+ delivery" note on the old ones.
